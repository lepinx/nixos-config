# gentle-shell migration

Make `gentle-shell` the single agent entrypoint on top of the nix-managed Pi, remove the Codex CLI, and keep every piece of agent config versioned and reconstructable. Route: Path A standalone launcher with the launcher's isolated home under `~/.gentle-shell`, so `~/.pi` is neither written nor read.

## Specs

**S1.** "queria migrarme a gentle-shell" — gentle-shell is the only entrypoint the user launches; the harness (gentle-ai, ODD, subagents, Engram) must be loaded by default, never a bare Pi. Concretely: `gentle-shell` resolves and works from a clean shell, loads `gentle-pi`, and keeps its isolated home at `~/.gentle-shell/agent` with the CLI state at `~/.gentle-shell/gentle-ai`. Home Manager exports `GENTLE_AI_HOME` and `PI_CODING_AGENT_DIR` with both paths, so no launcher-free `pi` or `gentle-ai` run re-creates `~/.pi`.

**S2.** "tengo codex, que no voy a usarlo mas" — the Codex CLI is not installed by the flake and is not documented as a supported agent. The `nan` provider and the `openai` profile models (`openai-codex/*`) are provider/model ids, not the CLI: they are not removed by S2.

**S3.** "quiero dejar la config mas limpia posible.. y versionable con nixos" — every versioned file that Nix writes is still versioned, every runtime-owned file stays mutable, and `docs/mutable-state.md` plus `docs/development.md` describe exactly that split with no stale claims.

**S4.** "reportemos en issue esto" — the crash is reported against the upstream project without duplicating an existing report. Done: commented on Gentleman-Programming/gentle-shell#2580 (published 4.7.0 crash stack, catch-branch analysis), comment id 6728329169.

**L11** (decision change, on user request): RDD is back **on** for this clone. The `off` was never a config file — it was a clone-scoped override recorded in `.git/gentle-ai/review-transactions/rar-authority/v1/rdd-mode/gen-0000000001.json` (`mode:"off"`), which outranked the machine-wide `on`. The user's earlier attempts used the machine-wide toggle, which cannot clear a clone override, so the TUI kept answering `off (decided by clone_local)`. `gentle-ai review mode enable --cwd <repo> --scope clone` wrote generation 2 (`mode:"inherit"`); bound status now reports `global:"on"`, `clone_local:""`, `effective:"on"`, `source:"global"`. `gentle-ai review mode status` also rewrote the same generation file under the sibling `review-mode/rar-authority/v1/rdd-mode/` path, so that copy is **not** stale legacy state and must not be deleted: both stores carry identical `revision`. Nothing in this flake writes the override, so it survives rebuilds but is absent on a fresh clone, where RDD returns to its documented default of on.

**L13** (decision change, `0d8179c`): the versioned root moved from `configs/pi/` to `configs/gentle-shell/`, reversing the earlier "the repo path names the owner of the format" reasoning. Two findings settled it. The launcher is the only entrypoint, so the repo root now mirrors `~/.gentle-shell` instead of naming a home that no longer exists. And `profiles.json` had to stop being a symlink: `/gentle:profiles` rewrites the store with an atomic rename, which replaces a symlink with a regular file, and the next activation with `force = true` restored the link over it and silently discarded the edit — so the property `L3`/`T6` claimed ("the panel's edit lands in the repo") never actually held. `profiles.json` now joins `settings.json`, `mcp.json` and `persona.json` as a seeded regular file, and versioning a profile change is a manual copy back into `configs/gentle-shell/gentle-ai/profiles.json`, as `docs/development.md` states. The same commit also dropped the `codegraph` MCP server from `mcp.json`. That is a behaviour change inside a rename commit, recorded here so the record stays explicit: codegraph is reached through the harness `codegraph` tool and the `codegraph` binary, so the MCP server entry was redundant. `T6` and `T8` were corrected to the new path; the branch was merged into `main` and pushed, so `0d8179c` stays as published rather than being split.
