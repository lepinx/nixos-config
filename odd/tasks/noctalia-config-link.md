# Link Noctalia runtime overrides into the repository

## Objective
Make Noctalia's Settings UI writes land in a versioned repository file, so UI
tweaks are visible to `git`, survive reinstalls, and stop silently shadowing the
declarative Home Manager configuration.

## Problem and evidence
Noctalia loads two layers and the runtime layer always wins:

- `~/.config/noctalia/config.toml` → symlink to `/nix/store/…-home-manager-files/…`, read-only, generated by `programs.noctalia.settings` in `modules/home/desktop.nix`.
- `~/.local/state/noctalia/settings.toml` → regular mutable file written by the Settings UI.

Evidence:
- `src/cli/schema_config.h` documents the load order: every `*.toml` in the config dir, then the state-dir `settings.toml` overrides.
- `ConfigService::loadOverridesFromFile()` merges the override table after the config dir.
- Live shadowing found: `[dock] enabled = false` in the override file vs `dock.enabled = true` in `programs.noctalia.settings`, so the declarative value is dead. Same layer holds `[lockscreen_widgets]` and `[wallpaper.*]`.
- `noctalia config validate` reports two config defects: `widget.workspaces.display` is deprecated (now `label_source`/`show_labels`) and `shell.ui_scale` is an unknown setting (moved to `[accessibility] ui_scale`), so the intended 0.8 scale is currently ignored (`config export full` shows `accessibility.ui_scale = 1.0`).

Writable-link feasibility:
- `src/config/atomic_file.h` → `resolveAtomicWriteTarget()` canonicalizes a symlinked config path and writes through it (`throughSymlink = true`).
- `ConfigService::writeOverridesToFile()` → `writeTextFileAtomic()` writes `<target>.tmp` and renames onto the canonical target, so a symlink at the state path survives.
- `ConfigService::setupWatch()` also watches the symlink target directory for external edits, which gives live reload on repository edits.

Repository precedent: `modules/home/editors.nix` already links `configs/nvim/lua`, `configs/zed/*.json` with `mkOutOfStoreSymlink`.

## Constraints
- Keep the declarative base for infrastructure that the UI never touches.
- Never point the state file at a Nix store path: the UI must be able to write.
- No `force = true` on the state file: the first activation must be deterministic.
- Host activation (`just switch`) is the user's step; do not run it.
- TDD: not applicable; declarative Nix plus a read-only diagnostic script.
- Validation: `nix-instantiate --parse`, `just check`, `just build`.

## Layer ownership after this change

| Layer | File | Owner |
| --- | --- | --- |
| Base | `programs.noctalia.settings` → `~/.config/noctalia/config.toml` (store) | Nix: `shell.*`, `accessibility.*`, `idle.*`, `keybinds.*`, `theme.templates.*`, `lockscreen.enabled`, `wallpaper.directory`, `weather`, `location`, `battery`, `plugins` |
| Overrides | `configs/noctalia/settings.toml` → `~/.local/state/noctalia/settings.toml` | Settings UI and manual TOML edits; versioned in git |

Rule: a key present in the override file wins. The Nix layer must not keep a
duplicate value for a key the UI persists.

## Acceptance criteria
- The state file path is a symlink to `configs/noctalia/settings.toml` after activation.
- A UI change updates the repository file and appears in `git diff`.
- `noctalia config validate` reports no warnings for the declarative config.
- `just noctalia-diff` reports no shadowed keys. (Historical at the time of this task; the recipe was later removed.)
- `just check` and `just build` pass, or failures are recorded exactly.

file with identical content, so the symlink would silently never be created.
